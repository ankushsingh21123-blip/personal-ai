# Security — Ankush's Personal AI

## Threat model
A personal agent with shell + files + web + phone access can send, spend, delete and leak. This app copies the Claude Code / Codex model: deny-first, approval before anything irreversible, secrets never in chat/files, outside content treated as data.

## Controls (all tested — see tests/test.js and scripts/security-check.sh)
- **Network:** binds `127.0.0.1` only, never `0.0.0.0`. No CORS. No public ports. Tailscale only for cloud (Phase 6).
- **Auth:** `X-Anku-Token` on every `/api` route except `/api/health`. Token is a 64-hex random value generated on first start, stored in `.env.local` (mode 600, git-ignored). Wrong/missing token → 401 (tested).
- **Rate limit:** 60 req/min/IP on all `/api` routes → 429 after (configurable via `RATE_LIMIT_PER_MIN`, clamped 1–10000; the test runner raises it to 300 for its own server only). `POST /api/brain/test` and `POST /api/settings/test` are additionally limited to 10/min/IP.
- **Freeze:** `POST /api/freeze` stops every agent loop instantly (screen, phone, browser, routines, queue drain) **and** refuses new chat turns and direct tool calls (`/api/chat` → 423, `/api/tools` → 423; cycle-5 fix M-1 — freeze previously did not gate chat/tools). Frozen state persists in SQLite across restarts until the user unfreezes. Freeze is also available from the web UI, the desktop-agent indicator window, and Telegram `/freeze`.
- **Desktop control (Phase B):** the desktop agent (`desktop-agent.js`, laptop-only) listens on `127.0.0.1` only, with the same token auth. Every action is validated twice (server + agent): allowlisted actions only, normalised coordinates, no sensitive acts (credentials/OTPs/admin prompts) ever, destructive acts need an approved approval id, and the agent refuses to act when the foreground window is a UAC prompt. Every action is audit-logged with the screenshot hash + intended target.
- **Phone control (Phase C):** ADB commands are an exact-argv allowlist (`execFile`, no shell). Phone access needs an explicit per-session enable with a TTL (default 30 min, max 4 h) and stops on freeze. iOS has no screen control — messaging + Shortcuts only, labelled as such.
- **Browser use:** Playwright headless Chromium, https-only, no private IPs, no password-field typing, and NO submit/post/send action exists — a human submits. Proxy env vars are honoured; credentials in proxy URLs are stripped from every error message.
- **Messaging channels:** Telegram polls with a token from env only (never logged/returned), and **answers nobody until a chat id is configured** — fail-closed (cycle-5 fix H-3; it previously answered any chat until pairing). Once set, only that chat is answered; refused chats are logged (chat id only, never message text). Pairing via the Settings UI takes effect without a restart. WhatsApp (Baileys) cannot start without `WHATSAPP_ENABLED=yes` AND `WHATSAPP_SPARE_NUMBER_CONFIRMED=yes` AND `WHATSAPP_ALLOWED_SENDER` (the one allowed sender JID; cycle-5 fix M-4) AND the package installed; auth state lives in `data/wa-auth/` (git-ignored). Spare number only — never the primary. **Both channels refuse API keys pasted in chat** (`secrets.js` detection, before any other handling): the message is never forwarded to the agent, never stored, and the reply points to the Settings page. `/providers` on Telegram shows status + masked previews only.
- **Settings / API keys:** keys are written only through the validated `.env.local` writer (`settings.js`): allowlisted variable names only, every value validated before the file is touched, atomic temp-file + rename, mode 600, comments/order preserved, and the in-process env mirrored (no restart). The auth token (`ANKU_TOKEN`) can never be written through Settings. Endpoints are behind the same token auth + rate limit as every other `/api` route; the server binds loopback only, so the Settings page is reachable only from the laptop itself. Test results are stored with errors redacted; status endpoints return masked previews (last 4 chars) only, never full keys. Keys are **never synced** to the cloud node, never logged, never committed — the pre-push hook scans outgoing diffs for key patterns and private filenames and blocks the push on a match.
- **Replay screenshots:** screen-session PNGs live in `data/shots/` (mode 600, git-ignored, pruned to the latest 200). They are served only over the authenticated `/api/replay/shot/:id` endpoint (`Cache-Control: private, no-store`), never synced, and deleting a session deletes its files. Screenshots leave the machine only inside a vision call to the configured model provider — see `../PRIVACY.md`.
- **Clipboard / windows:** clipboard reads/writes are length-capped and their contents are never logged; audit entries record lengths only. Window control uses fixed PowerShell scripts with user input passed via `$args` only (no string-built commands); `open_app` is an allowlist of 9 apps.
- **Self-modification — REMOVED (cycle-5 fix H-4, audit 18 Nov 2026):** the agent **cannot** edit the app's own code. Tool writes to the `app/` directory (code, tests, served frontend), to `skills/approved.json`, and to `.githooks/` are refused by `assertWritablePath` in `tools.js` — enforced in code, not just by prompt. The old flow (agent edits code, `run_tests` gates it) was unsafe: `run_tests` executes the test script, so a turn that could rewrite the script or the tests could reach arbitrary code execution, and a frontend overwrite would enable stored XSS + token theft. The agent may still *read* app code, and `run_tests` remains as a health check (suite pass/fail counts, concurrency-guarded). Code changes are made by the human (see `../docs/CUSTOMIZE.md` for the propose → human-applies → agent-verifies flow). The shell allowlist stays read-only for git (`git status`/`diff`/`log` only), so the agent can never commit or push.
- **Routines (Phase E):** run through the same deny-first tools as a chat turn; approval rules can only be stricter, never looser; a SQLite run lock prevents double-runs; missed runs are recorded, never silently dropped.
- **Sync (Phase D):** last-write-wins per record with device + timestamp; conflicts are stored in `sync_conflicts` and surfaced, never silently overwritten. Sync transport is the app's own API behind Tailscale with token auth.
- **Input validation:** JSON body limit 100kb, text max 4000 chars, title/body length caps, provider names allowlisted, Settings values validated by kind (secret/url/model/int/order/chatid/bool/path) before writing. Secret values must not contain shell metacharacters (cycle-5 fix M-7 — a stored value must stay inert even if the file is ever read by a shell). `max_actions` on the screen loop must be an integer 1..50 (cycle-5 fix M-21). Error responses are mapped honestly: 400 for bad JSON/validation, 413 for oversized bodies, 423 when frozen, 429 when busy, 503 for a locked database, 504 when a turn exceeds its budget (cycle-5 fix M-24).
- **Turn budget & concurrency (cycle 5, H-11/M-19):** every agent turn — chat, Telegram, routines, queue — runs through one entry point with a 2-turn concurrency cap (shared by all callers; 429 when busy) and a whole-turn deadline (default 240 s, `TURN_BUDGET_MS`, clamped 30–290 s; 504 on timeout). Each provider call has its own 60 s timeout and output cap (`MAX_OUTPUT_TOKENS`, default 2048). The 2-turn cap previously lived only on `/api/chat`, so other callers bypassed it.
- **Usage accounting (cycle 5, H-13):** every provider result carries normalized token usage (`{prompt, completion, total, estimated}`); providers that report nothing get a labelled chars/4 estimate, never invented precision. Groq usage is counted daily in the settings table against `GROQ_DAILY_TOKEN_BUDGET` (default 200,000, the free-tier limit) — the chain falls through instead of spending past quota.
- **Dotenv parsing (cycle 5, M-7):** `.env.local` is parsed as data everywhere it is read — the server's loader and `scripts/load-env.sh` (used by the test runner) only accept `KEY=value` lines and never execute the file. A stored value containing `$(...)` stays literal text.
- **Database contention (cycle 5, H-16):** SQLite `busy_timeout` is 1000 ms by default (was a hard-coded 5000) so a contended write bounds its event-loop block; `PIPLET_BUSY_TIMEOUT_MS` overrides it (the test runner sets 5000 — it deliberately runs 8 processes against one DB file). WAL mode keeps readers unblocked. Honest limit: writes are still synchronous — a truly async write path remains future work.
- **Headers:** nosniff, DENY framing, no-referrer, CSP `default-src 'self'` + `img-src 'self' blob:` (blob only, so authenticated screenshot fetches can render via blob URLs; no remote images).
- **Tools — deny-first:** allowlist only (28 tools). Files/notes/web/shell as before, plus: `search_files`, `create_file`, `search_notes`, `notify`, `screenshot`, `screen_act`, `list_windows`/`focus_window`/`open_app`, `clipboard_get`/`clipboard_set`, `create_routine`/`list_routines`, `run_tests`, `create_approval` (draft only — approving never executes), `file_info`, `append_file`, `recent_activity`, and the Memory v2 tools `remember_fact`/`recall_memory`/`forget_fact`/`edit_fact` (scoped facts, hard-delete forget — see the Memory bullet below). Everything else — including `send_email`, `rm -rf`, `sudo` — is denied, logged in `audit_log`, and never executed. The native function-calling declarations mirror this allowlist exactly (enforced by a test). The shell allowlist is 6 exact read-only commands; `npm test` was removed in cycle 2 (it executed whatever `package.json` defines and ran live tests without a server, failing them misleadingly) — the `run_tests` tool is the sanctioned test path. Path rules (cycle 5): `search_files` skips secret/credential files and redacts key-shaped excerpts (H-1); symlinked parent directories are resolved before the workspace check, so a symlink cannot smuggle a path outside the workspace (H-2); writes to the app directory, the skills manifest, and git hooks are refused (H-4).
- **Audit chain + receipts:** every `audit_log` entry hashes the previous entry (SHA-256, `app/audit.js`), written inside an immediate transaction so concurrent processes cannot fork the chain. `GET /api/audit/verify` recomputes the chain; editing any chained entry fails verification (tested, with restore). Run receipts (`GET /api/audit/receipt`, JSON or Markdown) report only what the log shows. Honest limit: the chain is tamper-evident, not tamper-proof — anyone with write access to the SQLite file could recompute it; it catches accidental edits and casual tampering, not a determined attacker with DB access. Rows written before chaining (NULL hashes) are counted as legacy, never treated as tamper.
- **Web fetch:** `web_fetch` allows https only, re-validates the host on every redirect hop (max 3, manual redirect handling), and refuses loopback, RFC1918, link-local, and cloud-metadata addresses. Known limit (honest): DNS rebinding and exotic IP spellings (hex/decimal forms) are not covered — a hostile DNS answer could still resolve a public name to a private address. The fetch runs loopback-only with no credentials, so the residual risk is a read of a local HTTP service, not a write; fix by resolving + re-checking IPs before connecting if this ever runs outside loopback.
- **Memory v2 (cycle 4):** facts live in `memory_facts` + an FTS5 index in the same local SQLite file. Recall is keyword-based (FTS5 + recency + exact-topic boost) — no vectors, no embedding model, no synonym understanding; the FTS5-vs-sqlite-vec decision and its reasons are documented in `memory.js`. Every read/write filters on scope (SQL equality), so facts are invisible outside their scope. Contradictions supersede, never silently overwrite: the old row is kept as history and recall attaches it. Forget is a hard DELETE (FTS trigger removes the index entry in the same statement). Fact content is never written to the audit log (tools audit metadata only) and memory tables are **never synced** (enforced by a security check — `memory_facts` is absent from `SYNC_TABLES`). The UI exposes view/edit/forget over the same token-authenticated API; `GET /api/memory` is the JSON export. Known limit: recall quality is keyword quality — paraphrased queries may miss facts.
- **Secrets:** `.env.local`, `data/*.db`, `data/shots/`, `data/wa-auth/`, `node_modules/` are git-ignored (checked by security-check.sh, both `.gitignore` files). No key pattern in tracked files, and no key pattern in staged changes (checked). `.env.local` is mode 600. Keys are never logged or returned by any endpoint — `/api/status` and `/api/settings/providers` report only whether a provider is configured plus a masked preview, never the key. Notifications, audit log, outbox, settings, screen sessions, and memory facts are **never synced** (checked).
- **Approvals:** send/post/spend/delete create a `pending` approval record only. Approving it records the decision — it does **not** execute the action. A human sends/posts/spends.
- **Prompt injection:** outside content (web pages, files, messages from anyone other than Ankush, recalled notes) is data, never instructions. Tool args are validated, paths are confined to the workspace, shell is allowlist-only.
- **Skills (cycle 3):** text only — a skill can never add a tool or widen a permission (`tools.execute` never reads skills; enforced by tests, including a skill whose body claims new powers). A skill loads only when `skills/approved.json` holds an approval whose sha256 matches the file; unapproved, edited, or corrupt states fail closed. Approval happens only via the human-run `scripts/approve-skill.js` CLI — no API endpoint can approve a skill. Third-party skills are never auto-installed; `skills/_drafts/` is ignored by the loader. See `../docs/SKILLS.md`.
- **Dependencies:** Express 5.3.0 + Playwright (plus Node built-ins). `npm audit` is skipped on this VM (audit endpoint unreachable) — re-run on the laptop before first use there. The pre-push hook (`../.githooks/pre-push`, enabled via `git config core.hooksPath .githooks`) re-runs the full security suite before every push.

## What the agent must never do
Send, post, spend, delete originals, change access, share credentials, approve security/admin/OTP prompts, bypass bot checks / Cloudflare / YouTube AI rules — all Ankush-only, or draft-first with his yes.

## If a key ever leaks
Rotate it immediately (that provider's own console — Google AI Studio, Groq, OpenAI, or Anthropic), check `audit_log` in the SQLite DB, and tell Ankush which key and when.
